# 并行协作

并行是降低等待时间或获得独立结论的优化手段，不是默认仪式。只有收益大于拆分、同步和集成成本时才使用子代理。

## 适用条件

同时满足：

- 至少两个子任务可独立理解，并有各自可观察的完成标准；
- 写入文件、模块或数据结构不重叠，或其中一个明确为只读分析；
- 接口和依赖已足够稳定，不需要子代理共同决定同一设计；
- 主流程下一步不会立即被其中一个结果阻塞；
- 每个子任务都能用简短提示说明范围、产出和验证。

共享热点文件、连续决策、同一根因调查、同一数据库/API 契约尚未确定，或只有一个关键阻塞点时，由主代理直接完成。

## 拆分契约

每个子任务必须写明：

- **目标**：要交付的可观察结果；
- **输入**：必要上下文和依赖，不倾倒整个仓库；
- **允许范围**：可读区域与独占写入文件；
- **禁止范围**：不得改动的共享文件、接口和无关功能；
- **接口约定**：与其他子任务交换的数据、类型或调用边界；
- **验收证据**：需运行的聚焦检查及返回内容；
- **返回格式**：状态、修改文件、验证结果、风险和未解决事项。

接口尚未稳定时，先由主代理确定最小契约，再并行实现；不要让多个代理分别发明互不兼容的接口。

## 工作方式

1. 先确定主代理立即推进的关键路径；不要把下一步必需结果委派后空等。
2. 选择真正独立的 sidecar 或 disjoint write set，避免重复分析和同一热点文件的并发修改。
3. 使用当前会话提供的代理工具；工具不可用时由主代理顺序完成，不等待或编造调用。
4. 子代理运行期间继续非重叠工作。仅在下一步确实依赖结果时等待，不重复轮询。
5. 返回后检查实际 diff、越界修改、接口一致性和证据；不要直接信任“已完成”摘要。
6. 在集成状态运行一次覆盖共享边界的最小充分验证。单个子任务的绿色结果不能证明组合后正确。
7. 子代理完成或不再需要时及时关闭；不保留无用途的并发任务。

## 质量与升级

普通小任务不分派子代理，也不为每个实现任务强制增加审查代理。高风险、安全、迁移、公共接口或大范围改动可以增加一个独立只读审查，但必须有明确审查问题。发现写入冲突、接口漂移、重复工作或集成失败时停止继续并发，由主代理收敛设计、重新划分边界或顺序完成。
