# 执行与恢复检查表

只在任务较长、跨会话恢复或依赖较多时使用；短任务仍需目标和完整清单，但不需要额外记录。

## 开始或恢复
- 执行依据：明确的用户请求、已确认需求摘要或现有计划路径；已有实施授权：
- 总体目标、成功标准及记录位置；目标工具是否满足调用条件或已采用文本记录：
- 是否已在修改前为全部任务创建 todos：
- todos 是否包含最终集成验证、交付核对和本地 commit：
- 恢复时是否复用同一目标与任务清单，没有覆盖不相关目标：
- 当前分支与工作区已有修改归属：
- 需求/计划中的路径、接口、依赖和命令是否仍有效；已自主修正的细节：
- 已完成任务及可验证证据：
- 下一个满足依赖的任务：

## 单任务检查
- todo 的目标和完成条件是否仍清楚：
- 允许修改范围与禁止范围：
- 前置接口/数据是否已经存在并通过验证：
- 聚焦验证命令和关键预期：
- 实际修改、验证结果和发现的计划偏差：
- 唯一进度源中的状态是否和证据一致；已有计划标记是否同步：
- 范围内的实现决定是否自主推进，没有设置重复确认关卡：

## 数据库任务（仅涉及 SQL 时）
- 目标环境、数据库和 schema/租户范围是否明确；凭据是否来自现有配置且未输出：
- 所需 SQL 是否属于默认授权；生产写入、删除或不可逆操作的具体授权依据：
- SQL 工作、影响范围、恢复方式和结果验证是否纳入清单：
- 实际影响行数/状态和脱敏证据；失败后是否核实生效状态再决定重试：

## 检查点
在进入依赖任务前确认：
- 当前任务的 diff 与计划范围一致；
- 公开接口、数据、权限和错误语义未发生未批准变化；
- 必要验证已通过，失败/跳过/环境阻塞已准确记录；
- todos 与计划完成标记均和证据一致；
- 下一任务的依赖已满足。

## 完成与提交
- 全部实施任务、成功标准及必要收尾 todos 的真实状态：
- 最终集成验证及结果：
- `lean-delivery` 交付核对结果：
- `git-handoff` 本地 commit 标识、提交范围和提交后状态；或不适用、用户豁免、无法提交的具体原因：
- 总体目标完成状态；只有最终验证和适用的必需提交已完成才可标记完成：
- 未授权执行 push、PR、合并、发布、部署或清理：

## 中断交接
- 已完成：
- 当前阻塞或未完成：
- 已自主尝试的排错与可继续的独立任务；真正缺少的输入、授权或外部条件：
- todos 当前状态：
- 总体目标当前状态；未更新时说明原因：
- 下一步：
- 需要重新运行的验证：
- 已知风险和不可丢失的上下文：
