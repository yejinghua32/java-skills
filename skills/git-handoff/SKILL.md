# Git 交付

普通任务的本地 commit 在任务完成且验证通过后允许但不强制；由 `subagent-driven-development` 交接或用户明确要求提交时，本地 commit 是必需交付项，满足条件后直接执行，无需再次确认。`push`、创建 PR、合并、发布和清理是彼此独立的授权，不得由前一个动作推导后一个动作。

## 通用检查

1. 只读取与请求动作直接相关的 `AGENTS.md`、贡献指南、Git/PR 模板和目标分支约定，不预先加载无关流程。
2. 检查当前分支、工作区、暂存区、未跟踪文件和必要的远端关系，区分本次改动、用户已有修改、生成物和无关文件。
3. 复用仍然有效的验证证据；代码再次变化、目标动作扩大影响或仓库门槛要求时才补充验证。
4. 检查最终 diff 是否符合完成标准，是否包含凭据、个人数据、内部地址、调试输出、大型生成物或意外依赖/锁文件变化。
5. 不使用 reset、clean、强制 checkout、stash、覆盖或删除来绕过脏工作区。无法安全归属文件时保留现场并停止。

## 本地提交

自动本地 commit 前必须同时满足：任务完成；风险相称的关键验证通过；验证后相关文件未变化；diff 只含当前主题；用户未要求不提交。

只暂存当前主题文件，并在提交前检查：

- `git diff --cached --stat`：范围与预期一致；
- `git diff --cached`：没有无关修改、临时产物或敏感信息；
- 提交信息遵守项目约定并描述真实行为，不编造 issue、测试或兼容性结论。

必需提交不得仅因改动小而跳过。用户明确要求不提交或验证后没有实际差异时，分别记录豁免或不适用，不创建空提交；目录不是 Git 仓库、关键验证失败、提交失败或归属不清时保留现场并报告未满足条件，不强行提交。不得擅自初始化仓库、修改 Git 身份或绕过 hook。不要为了得到单一 commit 改写、压缩或丢弃用户历史。

用户已有暂存内容也属于受保护修改，不能随本次提交夹带，也不能擅自取消暂存；无法在保留其状态的前提下隔离本次变更时，报告提交受阻。提交成功后读取实际 commit 标识，核对提交文件与提交后状态，再向调用流程返回提交证据；未成功时不得把提交 todo 标为完成。

## 其他动作

- **推送**：仅在用户明确要求时，确认远端、当前分支、upstream 和将上传的 commit；拒绝意外推送其他本地提交。
- **创建 PR**：仅在明确要求时，读取 PR 模板和目标分支规则，检查完整分支 diff、提交历史、验证摘要、兼容/迁移影响和真实风险；不使用占位内容。
- **合并**：仅在明确要求时，确认 PR/目标分支、审批与 CI 状态、冲突风险和合并策略；合并后在结果上重新检查必要证据。
- **发布/部署**：不能从 merge 授权推导；必须单独确认环境、版本、变更内容、回滚和健康验证。
- **清理**：确认提交已安全存在于预期目标、工作树归属明确且可恢复；删除分支、工作树、标签或丢弃修改前必须再次获得明确确认。

不要自动 `git pull`、force-push、改写共享历史或展示固定收尾菜单。发生冲突、关键验证失败、远端状态意外或授权不明确时停止并报告，不强行推进。
