# 风险分级验证

验证的目标是用最小成本推翻错误实现，而不是机械追求命令数量、覆盖率数字或全绿外观。

## 先找权威入口

按优先级选择命令：项目 `AGENTS.md`/贡献指南 → 仓库脚本和 CI → Maven/Gradle/npm 等 wrapper 与模块任务 → 工具默认命令。保持已有包管理器、profile、数据库替代和测试分层；不通过跳过测试、关闭检查或更换工具获得绿色结果。

## 选择验证范围

| 风险 | 典型改动 | 默认最小证据 |
|---|---|---|
| 机械/文档 | 文案、注释、格式、静态示例 | 最终内容和 diff；有廉价格式、链接或解析检查时运行 |
| 低 | 局部可逆逻辑、样式、小范围配置 | 最近单元/组件/语法检查，覆盖主要行为 |
| 中 | 业务规则、内部接口、多个关联文件 | 目标测试 + 受影响模块的类型、lint、构建或集成检查之一 |
| 高 | 权限、支付、迁移、公共 API、并发、部署、共享基础设施 | 目标测试 + 相关集成边界 + 项目要求的静态/构建检查；影响真正扩展到全局时才跑完整套件 |

## 测试应能证伪行为

一个有效测试应包含可观察输入和结果，预期来自需求、独立规则或已知样例，而不是复制生产算法。写完后回答：哪一个合理的错误改动会让它失败？答不出来时，增强测试或诚实标注其只检查结构/文档契约。

按最能发现真实失败的边界选择：

- 纯逻辑和边界值：单元测试；
- API、序列化、校验、错误和权限：契约、Web/API 或集成测试；
- 查询、映射、事务和迁移：使用项目支持的数据层集成路径；
- UI 状态和交互：组件测试，跨系统关键旅程才使用 E2E；
- 构建、配置、模板和文档：解析、构建、lint、链接或渲染检查。

不要求每层都新增测试，只覆盖改变的契约、最高风险失败路径和必要集成点。

## 高风险最低场景

只检查适用项：

- **认证/授权**：合法、未认证、权限不足、错误资源所有者、跨租户；
- **支付/幂等/队列**：成功、重复请求、依赖失败、重试上限和部分完成；
- **迁移/数据**：已有数据、空值和边界、重复执行、并发访问、失败恢复或 dry-run；
- **公共 API**：正常响应、无效输入、错误结构、调用方兼容和版本重叠；
- **前端交互**：加载、成功、空态、错误、重复提交和权限状态。

## 是否新增测试

新增测试应稳定捕获新行为、回归 Bug、边界、契约或安全规则。纯文档/格式、机械重命名、已有测试直接覆盖、只能镜像实现细节或维护成本明显高于风险时，可以不新增；说明采用的替代证据。

## 结果解释与停止条件

记录精确命令、范围、退出状态和关键结果，区分通过、失败、跳过、无法运行、不稳定和已有基线失败。关键门槛失败时不得声称可安全合并或部署；无关基线失败不得通过修改测试或生产代码掩盖。

当选定检查通过、验证后相关文件未再变化、没有证据表明影响扩大时停止。代码再次变化、共享契约受影响或结果不稳定时，才重跑或升级验证范围。
